# GPX2MAP

GPXのトラック・ルート・ウェイポイントを国土地理院の地図に重ね、印刷用のA4横PDFを作成するアプリです。日本語の画面とコマンドラインで利用できます。

[Webアプリ](https://huggingface.co/spaces/yuishin/gpx2map) / [GitHub](https://github.com/yuimaisa/GPX2MAP)

## 画面での使い方

1. **GPXファイルを選ぶ**：GPSや登山アプリから書き出した `.gpx` ファイルを選びます。容量、座標点数、トラック・ルート・区間数、概算距離を確認します。
2. **印刷設定を決める**：標準地図・淡色地図・空中写真と、`1:25,000`・`1:50,000`・`1:100,000`・その他の縮尺を選びます。余白やページの重なりは「詳細設定」で変更できます。
3. **地図の配置を確認する**：青い枠が1ページ、赤い線・点がGPXです。配置図の番号はPDFのページ順と同じです。予定ページ数と概算タイル数も確認できます。
4. **PDFを作成して保存**：「PDFを作成」を押します。タイルの準備数とページ作成数が表示されます。完了したら「PDFをダウンロード」から保存します。PDF容量が上限を超える場合はページ単位で自動分割し、「ZIPをダウンロード」からまとめて保存できます。GPXを分割する必要はありません。

ZIPを展開すると、`map_part001_pages001-006.pdf` のように連番と全体のページ範囲を含むPDFが入っています。連番順に印刷してください。PDFビューアーのページラベルも全体の通し番号を維持します。分割は各PDFの実ファイル容量で判断し、各ファイルが上限以下になるようにします。地図の細かさに応じて、1ファイルに入るページ数は変わります。ページの配置・重なり・縮尺・JPEG品質は変更しません。

印刷するときは **A4・横向き・倍率100%（実際のサイズ）** を指定してください。「用紙に合わせる」では指定した縮尺になりません。コンビニ印刷では四辺5mmの余白を目安にしてください。

地図上1cmは `1:25,000` で250m、`1:50,000` で500mです。対象範囲の中央緯度を基準に縮尺を計算します。Webメルカトル投影による範囲内の縮尺変動が1%を超える入力は拒否します。地球の曲率・投影・画像の丸めによる微小な誤差があります。

異なるトラック区間やルートは線で接続しません。ウェイポイントはそれぞれ独立した点です。概算距離は各区間内だけを球面距離で合計し、区間間やウェイポイント間の距離を含みません。

## 対応範囲と制限

| 項目 | 上限・範囲 |
| --- | --- |
| Python | 3.12（検証対象） |
| GPX容量 | 5MiB |
| 座標点数 | 50,000点 |
| XML構造 | 深さ32、要素200,000まで。DTD・外部エンティティは拒否 |
| 緯度・経度 | 有限の数値。緯度±85.0511287798066度、経度±180度以内 |
| 縮尺 | 1:12,500〜1:250,000（内部パラメータ0.1〜2.0） |
| 四辺の余白 | 0〜20mm |
| ページ間の重なり | なし・少なめ・標準・多め |
| PDFページ数 | 24ページ |
| ページ計画の候補セル数 | 2,000セル、交差検査2,000,000回 |
| 取得するタイル | 重複を除いて800枚 |
| PDF容量 | 1ファイルあたり64MiB。超過時はページ単位で分割してZIPを出力 |
| 処理用メモリの推定上限 | 384MiB。サーバープロセス全体の上限とは異なる |

地図データは提供元の収録範囲に限られます。日付変更線をまたぐような広範囲のデータは区間を分けてください。1ページに広い範囲を収める縮尺ではタイル数が増えるため、必ずしも処理が軽くなるわけではありません。

磁北線は初期状態でONです。「詳細設定」の「磁北線を表示する」で切り替え、ONの場合のみ500m・1km・2kmの間隔を選べます（初期値1km）。地図領域だけに薄い青の平行線を描画し、その上に赤いGPXを描画します。印刷余白、左下の縮尺・スケールバー、右下の出典の配置は維持しています。

偏角はNOAA/BGSの標準 **World Magnetic Model 2025（WMM2025）** を `pygeomag==1.1.0` に同梱された係数からオフライン計算します。東偏を正、西偏を負とし、西偏の線は左上、東偏の線は右上へ傾きます。以前のHTTP 404を返す地理院の偏角APIは使用しません。

全ページの地図範囲の中心を計算地点とし、標高はWGS84楕円体上0km、計算日はPDF生成日の日本時間（JST）です。GPXの記録日は使用しません。全ページで同じ偏角・原点・縮尺基準を共有し、重複部分でも線が揃います。間隔は線に直交する地上距離をWebメルカトルとページ計画の基準緯度で換算し、1kmは1:25,000で紙面上40mm、1:50,000で20mmです。

偏角・西偏/東偏・モデル名・計算日を地図左上に各ページ表示します。磁北線OFFでも情報欄を残すため計算は行います。**WMM2025の適用期間は2025-01-01〜2029-12-31** です。期間外や計算失敗は原因を表示してPDF生成を失敗扱いにし、無断の外挿や磁北線の省略による正常終了はしません。

偏角と縮尺は代表地点・緯度による登山地図向けの近似です。範囲内の偏角変化や局所的な磁気異常は補正しません。投影の縮尺変動が1%を超える範囲は従来どおり拒否します。

必要なタイルが1枚でも取得できない場合、PDFは提供しません。灰色の代替画像で正常完了に見せたり、欠けたPDFを提供したりしません。

## ローカルで実行する

Python 3.12を用意し、プロジェクトのディレクトリで実行します。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Windowsでは仮想環境の有効化を `.venv\Scripts\activate` に置き換えてください。日本語フォントは `assets/` に同梱しているため、初期表示・生成時のフォント取得は不要です。

`.streamlit/config.toml` でもアップロード上限を5MiBに設定しています。デプロイ時もこの設定ファイルを含めてください。

### コマンドライン

```bash
python gpx2map.py -i tests/fixtures/sample.gpx -o map.pdf
python gpx2map.py -i tests/fixtures/sample.gpx -o map-50000.pdf -s 0.5 -t pale
```

| 引数 | 説明 | 初期値 |
| --- | --- | --- |
| `-i`, `--input` | 入力GPX。必須 | — |
| `-o`, `--output` | 出力PDF。自動分割時は拡張子を `.zip` に変更 | `output.pdf` |
| `-s`, `--scale` | 0.1〜2.0。縮尺は `1:(25,000 / s)` | `1.0` |
| `-m`, `--margin` | ページ間の重なり。0〜1タイル | `0.5` |
| `-t`, `--type` | `std`・`pale`・`seamlessphoto` | `std` |
| `--page-margin` | 四辺の余白。0〜20mm | `5.0` |
| `--cache-dir` | 公開タイルのキャッシュ先 | 一時領域の `gpx2map-tile-cache` |
| `--draw-magnetic-north` | 磁北線を表示 | ON |
| `--no-magnetic-north` | 磁北線を非表示（偏角情報は表示） | — |
| `--magnetic-spacing` | 磁北線の地上間隔。500・1000・2000m | `1000` |

画面の重なり「なし・少なめ・標準・多め」は、CLIではそれぞれ `0`・`0.25`・`0.5`・`1.0` に対応します。画面とCLIは同じ入力検証・ページ計画・生成処理を使います。

成功時の終了コードは `0`、入力・通信・生成失敗時は非ゼロです。エラー理由は標準エラーへ出力します。実際の保存先を表示します。失敗時には既存の出力を置き換えません。自動分割時は、たとえば `-o map.pdf` に対して `map.zip` を原子的に保存します。

## エラーが出たとき

| 表示・状況 | 対応 |
| --- | --- |
| GPXを読み込めない／有効な座標点がない | 書き出し元でトラックやルートを含め、GPXとして書き出し直してください |
| 容量・点数・ページ数・取得量の上限超過 | 対象区間を分けるか、点数を減らしてください。1ページの取得量超過では、1:25,000などの詳しい縮尺も試せます |
| HTTP 404 | 提供元に該当する地図がない可能性があります。地図の種類・対象範囲を確認してください |
| HTTP 403 | 取得先へのアクセス制限を確認してください。認証や権限を自動変更する機能はありません |
| HTTP 429、タイムアウト、HTTP 5xx | 自動再試行後も失敗した場合、時間を置き、通信状況を確認して再試行してください |
| 日本語フォントを読み込めない | `assets/NotoSansJP-Regular.otf` が配布物に含まれているか確認してください |
| PDF容量の上限超過 | 自動分割してZIPで保存できます |
| 1ページだけでPDF容量の上限超過 | 該当する通しページ番号・実容量・設定上限を表示し、出力を中止します。画質・縮尺を自動で落とさず、容量上限の設定や地図の種類の変更を案内します |

設定やファイルを変えると古い配置図・見積もり・PDFは無効になります。生成失敗後も、ファイルや設定を修正して再試行できます。

## 取得・キャッシュ・メモリの設計

地理院タイルのズームレベル15を使い、リクエスト開始間隔をプロセス全体で最低0.15秒空けます。取得は直列で、429・一時的なサーバー障害・通信失敗・不正画像は最大3回まで再試行します。403・404は再試行しません。取得画像は256×256かつ2MiB以下を確認します。

公開タイルのみを原子的にキャッシュ保存し、同一タイルの並行取得を制御します。容量上限は512MiB、保持期限は取得から30日です。`GPX2MAP_CACHE_DIR` またはCLIの `--cache-dir` で保存先を指定できます。画面はセッションごとに環境変数を書き換えません。

巨大なタイル結合画像は作らず、最終印刷サイズのキャンバスへ貼り付けます。JPEG品質95・サブサンプリングなしで1ページずつ保存し、ラスター画像を閉じます。`pdf_output.py` はこのJPEGを再圧縮せず、64KiBずつディスク上のPDFへコピーします。ページツリー・相互参照表・トレーラーを含む完全なPDFを書いて実容量を確認し、超過した場合は最後のページを取り戻して、確定したPDFをディスク上のZIPへ追加します。同じページを次のPDFの先頭に移します。ページ計画やGPX区間の切り直し、全ページ分の巨大PDFを作ってからの分割は行いません。JPEGはそのページの処理後、確定したPDFはZIPへの追加後に削除します。途中で失敗した場合、部分的なZIPをダウンロードとして公開しません。

画面のセッションにはダウンロード用ファイルの参照を保存します。Streamlit標準のダウンロードボタンはファイル全体をサーバーメモリへ読み込むため、同梱コンポーネントで8MiB以下のブロックを順番に取得し、ブラウザーで元のPDF／ZIPにまとめて保存します。ブラウザー側にはダウンロード全体を扱うためのメモリが必要です。ダウンロードの失敗時は再試行できます。保存用ファイルは結果ごとのランダムなパスに置き、設定変更・再生成・セッション破棄時に削除します。

メモリ見積もりは、3508×2480×4バイトのページバッファ3枚分（約99.6MiB）と、GPX・タイル・エンコーダーなどの64MiBを合計した約163.6MiBです。これは処理量制御用の推算です。Streamlit、Python、OS、アップロード済みデータなどを含むサーバー全体の使用量とは異なります。PDF描画はプロセス内で1件ずつ処理し、各セッションは独立した入力・設定・生成計画を持ちます。

Pythonから大きな結果を扱う場合も、`with generate_output(...) as result:` の `result.path` と `result.parts` を使ってください。互換用の `generate_pdf()` はPDFまたはZIP全体を `bytes` で返すため、大容量の出力には使用しません。

## テストと検証

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -v
```

通常テストは外部通信不要です。小規模なGPXフィクスチャをリポジトリに含めています。経路の線分全体の被覆、区間境界、入力とリソース制限、タイル取得の異常系、キャッシュ・同時利用、PDFのページ数・A4寸法・印刷縮尺・画像内容、CLI終了状態、画面の再試行を確認します。分割については容量上限ちょうど／1バイト超過、容量の異なるページ、最終端数、10ページ以上の通し番号、1ページ超過、分割途中の失敗・一時ファイル削除を確認します。分割前後のJPEGバイト列の一致と、重なりなしのページ境界にある疎な経路の描画も検査します。

磁北線は西偏8°・東偏8°・0°、縮尺と間隔、重複ページの線位置、表示OFF、計算エラー、設定変更後の計画とPDFの無効化も検証します。公式WMM2025テスト値100件を許容誤差0.005°で照合します（出典は `tests/fixtures/README.md`）。

実ブラウザ検証は、アプリとPDF生成を動かし、地図タイルだけを決定的な画像に置き換えます。

```bash
python -m playwright install --with-deps chromium
python scripts/check_browser.py
python scripts/check_browser.py --split --base-path maps
```

デスクトップ1280px・スマートフォン390pxで、アップロード、入力エラー、生成、PDF／ZIPダウンロード、横はみ出しを確認します。分割ケースではURLプレフィックス、多数のダウンロードブロック、一時的な通信失敗後の再試行も検証します。システムの `chromium` があればそれを使い、`GPX2MAP_CHROMIUM_PATH` でも指定できます。結果は `test-results/` に保存します。

実タイル取得・キャッシュ再利用とPDF生成の確認は別に実行します。通信が必要なため通常のCIテストからは分離しています。

```bash
python scripts/check_services.py --pdf --check-magnetic
python scripts/check_browser.py --live
```

メモリの再確認はLinuxで次を実行します。50,000点・24ページの合成データと模擬タイルを使い、コア処理の最大RSSを計測します。実タイルやHugging Face環境の負荷検証を代替するものではありません。

```bash
python scripts/check_memory.py
python scripts/check_memory.py --split
```

## 依存関係とデプロイ

`requirements.in` は直接依存、`requirements.txt` はPython 3.12で解決した推移的依存を含む固定バージョンです。`requirements-dev.txt` はテスト・ブラウザ検証用の追加依存です。更新時はクリーンなPython 3.12環境で `requirements.in` をインストールして `pip freeze` を取り、開発用パッケージを混入させず、全テストとブラウザ確認を実施してください。

GitHub Actionsはプルリクエストとmainへのpushで単体・統合テストとブラウザ検証を実行します。両方が成功したmainへのpushだけが、既存の `HF_TOKEN` シークレットでHugging Face Spacesへ同期されます。PRのブランチpushではデプロイしません。Spaces側はREADME先頭のPython 3.12・Streamlit 1.66.0と、固定された依存関係を使用します。

デプロイはテストと同じコミットをチェックアウトし、デプロイ専用の `requirements-deploy.txt` をインストールして `scripts/deploy_space.py` を実行します。`HfApi.upload_folder()` が `yuishin/gpx2map` に配布し、バイナリの処理はSDKに任せます。一時Gitリポジトリや通常の `git push` は使いません。

配布対象は実行用Python 7ファイル（`magnetic_north.py` を含む）、`requirements.txt`、README、アプリのLICENSE、`.streamlit/config.toml`、日本語フォント、OFL、フォント説明の14ファイルです。明示したファイルだけを配布フォルダへコピーし、必須ファイルの欠落やフォントのGit LFSポインターを検出すると送信前に失敗します。`.git`、`.github`、テスト、キャッシュ、仮想環境、デプロイ用SDKは含めません。既存のSpace上のファイルを一括削除する処理は行いません。

配布対象の確認は、トークンや外部通信なしで実行できます。

```bash
python scripts/deploy_space.py --dry-run
```

`HF_TOKEN` はアップロードのステップだけでGitHub Secretsから受け取り、SDKへ渡します。トークンを含むURLや例外の詳細はログに出力しません。実アップロードには、既存のSpaceへ書き込めるトークンが必要です。

単体・統合テストに加え、CIで50,000点・24ページの合成データによるメモリ確認も実行します。

初回公開前にはSpacesのビルドと起動、実地図の取得、対象環境でのメモリ使用量を確認してください。今回の改善で外部サービスの資格情報やリポジトリの権限設定を変更する必要はありません。
